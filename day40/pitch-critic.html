        The System Prompt

        The assistant is a single-purpose critic, not a general chatbot. The system prompt locks Claude into one role — a blunt, expert VC doing first-read diligence — and one output contract: a strict JSON object matching the dashboard's data shape. This keeps the UI deterministic: no parsing prose, no guessing where the "score" is hiding in a paragraph.

        Key design decisions in the prompt:

        • Role framing over persona decoration. Instead of "act like a fun VC," it defines the actual judgment criteria a real early-stage investor uses (problem urgency, market size, unit economics, team-market fit, defensibility) so scores are grounded, not vibes.
        • Forced structure. Claude must return six fixed categories with 0–100 scores plus a one-line note each — this stops score inflation from vague enthusiasm and makes the dial/bars always renderable.
        • Verdict logic is rule-based, not vibes-based. The prompt defines score bands that map to GO / MAYBE / NO-GO, so the stamp is consistent with the numeric score instead of Claude picking a mood independently.
        • Edge cases handled explicitly: missing/thin fields get penalized in relevant categories rather than the model inventing details; irrelevant or joke submissions get a low score and an honest note rather than a fabricated critique; abusive input is declined without breaking the JSON contract.
        • No sycophancy clause. The prompt explicitly forbids hedging language ("this could work if...") in favor of direct verdicts, matching the "blunt VC" tone the user asked for.
        

    
        Why the UI looks like this
        
    
        The interface is styled as a confidential deal memo rather than a chat window, because the mental model here isn't "talk to an AI" — it's "get judged by an investor." A dark, serious panel system with a serif masthead and monospace data labels borrows from the visual language of due-diligence documents and term sheets, not consumer apps.
        
    
          
      
        • The circular score dial and rubber-stamp verdict give an instant read before anyone scrolls — mirroring how a real investor decides fast, then explains why.
          • 
      
        • Category bars make the score legible and specific — a founder can see exactly which dimension (market, team, moat) is dragging the number down instead of arguing with one blended score.
          • 
      
        • Risks vs. strengths sit side by side, deliberately not stacked, so the read isn't lopsided doom — the blunt tone still gives credit where it's earned.
          • 
      
        • The investor questions section exists because the real value of a pitch critic isn't the score — it's arming the founder with the hard questions before a real investor asks them.

        Extending this assistant
        
    
        Ways to grow this from a single-shot form into something more capable:
        
    
          
      
        • Add memory: store each submission's JSON in localStorage/a backend keyed by company name, and show score deltas across revisions ("Team score improved 12pts since last submission").
          • 
      
        • Add tools: give Claude the web_search tool so it can sanity-check market-size claims or check if competitors mentioned actually exist, and cite what it finds.
          • 
      
        • Multi-step flow: turn this into a conversation — after the verdict, let the founder ask "how do I fix the moat score?" and have Claude follow up conversationally using the original memo as context, rather than only doing one-shot scoring.
          • 
      
        • File input: accept an uploaded pitch deck PDF, extract slide text, and pre-fill the form fields automatically before scoring.
          • 
      
        • Comparative benchmarking: feed in category scores from real seed-stage companies (with permission/anonymized) so the dashboard can show percentile context, not just an absolute score.
